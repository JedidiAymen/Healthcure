# UX-05 · Model Lab

## Status

Implemented for review. The model registry now presents a source-linked methods catalog, domain filters, exact readiness counts, method provenance, license terms, operations, and the existing execution gates.

## What changed

- Replaced the long stack of generic method cards with a catalog/detail layout: choose a registered method, then inspect its source revision, license, operations, readiness, and gate explanation.
- Added domain filters for SurgiVision, DoseTwin, and FistulaGuard, and counts derived from the live model registry response.
- Kept each record's upstream link and added direct links into the matching scientific source workspace, even when inference or optimization is blocked.
- Preserved the original server-provided readiness and details. No predictions, benchmark metrics, checkpoint identities, or license claims are generated by the interface.
- Kept the pinned CVS-AdaptNet validation summary and its checkpoint-specific blockers visible.

## Scientific integrity

The registry currently contains seven methods and reports zero ready for execution. The design makes each blocked, unverified, or missing-dataset state explicit; execution remains fail-closed in the API. The `Inspect source workspace` action opens source review; it does not imply that a model run is available.
