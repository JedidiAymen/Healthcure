# Synthetic DoseTwin phantom demo

This is a deterministic local software viewer for demonstrating the DoseTwin inspection interface without installing or exposing research imaging files. It is not a clinical tool, benchmark case, treatment plan, or HackCure acceptance artifact.

## Open it offline

The phantom is generated by the API from the checked-in Python source; it does not need a remote download, a research dataset, a database record, or credentials. From a prepared checkout with the project dependencies installed, start the usual loopback-only launcher:

```sh
export MEDFORGE_API_PORT=18081
export MEDFORGE_WEB_PORT=15174
./scripts/start_local.sh
```

Open <http://127.0.0.1:15174/studio/dosetwin/cases/synthetic-dose%3Aphantom-v1>. It can also be opened through **Open synthetic phantom** on the Studio DoseTwin card. Stop the local services with Ctrl+C in the launcher terminal. The route works without OpenKBP files; the standard launcher still needs the application runtime dependencies described in [`RUN_LOCAL.md`](../RUN_LOCAL.md).

## Generated case and reproducibility

- Reserved ID: `synthetic-dose:phantom-v1`; dataset ID: `medforge-synthetic-phantom`; revision: `medforge-synthetic-phantom-v1`.
- Geometry: 128 × 128 × 128 voxels, with illustrative 2.5 mm spacing. A radius-54 water cylinder is represented as relative density 1 inside and 0 outside. This is not CT Hounsfield data or patient geometry.
- Structures: a radius-11 voxel sphere named `Target` centered at (64, 64, 64), plus axial radius-7 cylinders `OAR-Cylinder-A` and `OAR-Cylinder-B`, centered at (40, 64) and (88, 64).
- Dose field: deterministic analytic values `70 × exp(-((max(r − 11, 0) / 24)²))` inside the water cylinder and zero outside. These numbers use an arbitrary synthetic illustrative scale; they are **not physical Gy**, calibrated dose, or a prescription.
- Generator: [`apps/api/app/synthetic_dose.py`](../apps/api/app/synthetic_dose.py). Volumes are generated in memory and serialized as little-endian float32 for stable SHA-256 hashes.

In the local viewer, inspect linked axial/coronal/sagittal slices, the synthetic masks and illustrative dose overlay, deterministic descriptive DVHs, provenance hashes, and optional 3D mask surfaces. Synthetic chart axes, legends, stat headings, and API unit metadata identify the dose values as an arbitrary synthetic scale. The interface permanently labels the case **SYNTHETIC PHANTOM · NOT ANATOMY · NOT A TREATMENT PLAN**. The built-in API does not offer a report or export surface for this case.

## Strict separation and readiness

The synthetic case has a unique `synthetic-dose:` ID, `reference_kind=synthetic`, a synthetic-only coordinate frame and origin, and `status=synthetic-viewer`. It is not inserted into the OpenKBP registry, never uses an `openkbp:` ID, and cannot be submitted to analysis, prediction import, model, comparison, educator evidence, or report workflows. Its dose statistics are descriptive software outputs; a field name inherited from real DoseTwin schemas does not make the values physical Gy or official OpenKBP evaluator metrics. There are no patient records, medical images, inference, benchmark results, or clinical conclusions in this demo.

Local code and API evidence only establish that the software path can run on this machine. They do **not** establish organizer acceptance, a hosted URL, clinical validation, dataset/display rights, or completion of the HackCure L2 requirement. Keep real research arrays local and follow [`DEMO_DATA_POLICY.md`](DEMO_DATA_POLICY.md).
